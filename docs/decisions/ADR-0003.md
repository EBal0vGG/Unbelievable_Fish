# ADR-0003: Application and HTTP Layers for Deal

## Контекст
После стабилизации домена `deal` появилась необходимость открыть его наружу:

- принимать команды из HTTP и внешних интеграций;
- сохранять агрегаты и проекции через порты;
- публиковать доменные события вне домена;
- держать orchestration отдельно от бизнес-правил агрегата.

## Решение
1. Добавлен слой `internal/deals/app` как application layer над доменом `deal`
2. В `app` введены порты:
   - `DealRepository`
   - `ProjectionRepository`
   - `EventPublisher`
3. Сценарии работы со сделкой оформлены как отдельные use case-типы с `Execute(...)` и `CommandMeta`
4. Добавлен слой `internal/deals/http` на `net/http`:
   - отдельный `Router`;
   - пакет `handler` c handler-ами по сценариям;
   - request/response DTO;
   - mapping ошибок приложения и домена в HTTP status codes
5. Входящие события других доменов не помещаются в домен `deal`; они должны адаптироваться снаружи в команды `app`

## Последствия
- Домен `deal` остаётся чистым и не знает про HTTP, шину и хранилища
- `app` становится единым слоем orchestration для HTTP и event consumers
- Исходящие доменные события публикуются через `EventPublisher`
- Для следующих шагов можно независимо добавлять:
  - persistence adapters;
  - HTTP wiring в общее приложение;
  - inbound consumers для `LotPublished`, `AuctionWon` и других событий
